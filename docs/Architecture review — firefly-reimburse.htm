Centralize the auth token seam

Strong in-process
shared/auth/index.ts · model/use-transaction-data.ts · model/use-transaction-todo.ts · ui/AccountList.tsx · routes/transactions.tsx
Problem
getToken() reaches into localStorage from 4+ files. No single module owns the token — every consumer couples directly to the storage mechanism.
Solution
Thread the token through a dedicated seam. Two adapters: one reads localStorage (prod), one is injected (tests). Consumers call one interface, never touch storage.
Wins
  • locality: token logic in one module
  • leverage: 4+ call sites stop leaking
  • test surface: inject fake token, no localStorage mock
  • interface shrinks; storage detail absorbed

Collapse the duplicated fetch-and-map seam

Strong in-process
model/use-transaction-todo.ts · api/service.ts · lib/transaction.ts
Problem

Wins

Extract business logic from the TransactionPage module

Worth exploring in-process
ui/TransactionPage.tsx · model/interface.ts · lib/transaction.ts
Problem
TransactionPage computes outstandingTotal inline and reads ff:accountId from raw localStorage. Business logic sits in the UI module where tests can't reach it without rendering the full component tree.
Solution
Pull outstandingTotal into a pure selector in lib/transaction.ts. Account selection gets a thin localStorage adapter like usePinnedAccounts. UI stays a rendering shell.
Wins
  • locality: business rules live in model
  • test surface: pure function, no render needed
  • leverage: selector reusable by other pages
  • UI module becomes shallow on purpose

Batch the N+1 TodoSwitch queries

Worth exploring in-process
ui/TransactionTable2.tsx · ui/TodoSwitch.tsx · model/use-transaction-todo.ts
Problem
Each TodoSwitch renders useTransactionTodo(tid) — one useQuery per row. 100 transactions = 100 parallel API calls on mount. The interface leaks implementation details (per-row queries) into the rendering tree.
Solution
Lift the todo state into useTransactionData. The data hook returns transactions with their todo status already resolved. TodoSwitch becomes a pure toggle with no queries of its own.
Wins
  • leverage: one query, N consumers
  • locality: todo status co-located with data
  • test surface: toggle tested in isolation
  • interface shrinks; TodoSwitch delegates
Before — N queries
After — 1 query

Delete dead modules and fix the type-cast seam

Speculative in-process
ui/TransactionTable.tsx · model/interface.ts (AccountType) · lib/transaction.ts:52
Problem
TransactionTable.tsx is deprecated dead code. AccountType is an unused type. mapRawTransactionToRecord uses a double cast (as unknown as TransactionRecord) to paper over structural mismatches — the interface lies about what it returns.
Solution
Delete the dead modules. Fix the return type of mapRawTransactionToRecord so it structurally matches TransactionRecord without the cast. If the Firefly API shape differs, define a separate FireflyTransactionRaw type.
Wins
  • leverage: removing dead code shrinks surface
  • interface becomes honest about its shape
  • type errors surface real bugs at compile time

Top recommendation

Centralize the auth token seam

The auth token is the only cross-cutting concern that leaks across every module. It's also the easiest win — a small seam with two adapters (localStorage for prod, injected for tests) eliminates 4+ direct localStorage calls and makes every other module testable without mocking storage. Tackle this first because it unlocks cleaner testing for all subsequent deepening work.
